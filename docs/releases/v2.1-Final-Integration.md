# ICCRI Website — Final Integration Release

## Version

**2.1.0**

## What this is

One complete, self-contained project representing every approved
feature and architectural improvement through Platform Refresh v2.0.
This was a verification and consolidation milestone, not a rebuild —
every prior milestone was implemented in one continuously-evolving
working directory, so there was no manual merging to perform. The
work here was confirming that claim is actually true, rather than
asserting it, and closing the real gaps that verification found.

actual strict `tsconfig.json`, with minimal ambient shims for modules

`next/image`). Zero new diagnostics beyond the long-confirmed shim

milestone in this project's history. `npm install` / `npm run build`

deliberately unbuilt (no content-layer or search decision has been

## Deployment notes

- This package has not been through a real `npm install` / `npm run
  build` in an environment with package registry access — that step
  needs to happen in your deployment environment (or CI) before this
  becomes live, the same as every prior release in this project. The
  real `tsc` verification above is a strong signal, not a substitute.
- `next/font/google` fonts are fetched at build time — the build
  environment needs network access for that one step.
- No environment variables are required by anything in this
  repository — there is no persistence layer, no external API, no
  authentication.
- Standard deploy: `git add . && git commit && git push`, then let
  Vercel (or your existing deploy pipeline) run its own install/build.

## Known technical debt

Carried forward, nothing new introduced by this milestone:

- **Content gaps**: Working Papers and Future Publications sections
  remain genuinely empty — no fabricated content exists to put there.
- **Type reconciliation**: `types/publication.ts`/`types/monograph.ts`
  still exist as their own interface shape alongside `PublicationDetails`,
  populated from Domain data but not structurally unified with it
  (open since Phase 2A Stage 5).
- **Institutional Layer**: fully typed, entirely unpopulated, and
  intentionally paused per your direction — two layers of architecture
  (objects, workflows) with no real institutional data or operations
  behind either yet.
- **RC-1B** (deployment verification: CI/CD, runtime smoke testing)
  never formally closed as its own milestone — subsumed in practice by
  every subsequent release's own verification, but never given its own
  report.
- **Two non-blocking ESLint warnings** (`ConceptMap.tsx`, `Button.tsx`)
  open since RC-1.
- **`iccri-banner.png`** is used only as the Open Graph image — a
  deliberate decision not to force it into on-page content (aesthetic
  tension with the site's restrained visual language), still an open
  item if you want it used more directly somewhere.
- **`LeadershipCard`'s compact mode** on the homepage drops the
  personal founder-quote `ContributorCard` used to carry — mitigated
  by the "Full profiles" link, not fully replaced.

## Post-deployment checklist

1. Run `npm install && npm run build` in the real deployment
   environment (or let CI do it) — confirm it passes before treating
   this as live.
2. Visually confirm the favicon and Open Graph image render correctly
   once deployed (metadata file conventions are correct in source;
   worth a real browser/social-preview check post-deploy).
3. Spot-check the Leadership section on About and the homepage in a
   real browser — photo cropping (`object-cover` on a fixed
   160×160/192×192 box) was reasoned about, not visually tested.
4. Confirm `next/image` optimization is serving reasonably-sized
   variants of the leadership photos and logo in production (they're
   large source files — 1.8–1.9MB each — `next/image` should handle
   this automatically, but worth confirming in a real Lighthouse/
   PageSpeed check).
5. Re-run the nav/route audit once live (every `href` in
   `config/navigation.ts` and `Footer.tsx` against the deployed site)
   as a final confirmation that nothing 404s in production the way it
   didn't in this environment.
6. Decide, at your convenience, on `iccri-banner.png`'s on-page fate —
   flagged as debt, not resolved here.
